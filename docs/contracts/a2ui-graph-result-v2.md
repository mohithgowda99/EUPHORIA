# Graph tool-result envelope v2

Backend-only additive extension to a2ui-graph-v1. Human action requests, snapshots, SSE, graph input, and legacy native/form outputs are unchanged. Graph result is `{userAction:<unchanged source event>,euphoria:{contractVersion:1,surfaceID,revision,sourceSurfaceID}}`. Native client does not parse this provider-only result. `userAction` retains exactly name/surfaceId/sourceComponentId/timestamp/context. `euphoria` is explicitly EUPHORIA metadata, not an A2UI field; old source-event consumers can read only userAction. The graph provider tool result envelope has its own v2 schema, avoiding a silent change to the strict v1 result schema.

Metadata comes from current owned SQLite surface, never human values. A model can use revision as expectedRevision and sourceSurfaceID for its next partial graph call. Metadata conveys state, not approval or execution authority; every next operation is separately validated against current owner/session/revision/pending call. No read tool, new event channel or duplicated state is introduced.

Migration: additive actions.result TEXT column stores exact JSON output (including event timestamp/metadata) before human result delivery. Refusal entries store `{success:false,error}` before sending; their identity remains in existing call/turn payload. Old rows retain NULL; never invent past delivery evidence. Immutable action payload remains separate from result, preserving idempotency. Accepted and unknown effects are never resent after restart. No new client login/migration required.

Unpublished stale partial calls receive bounded failure feedback identifying current revision. If no source graph exists (including a previous native form), feedback requests createSurface/full components/model without expectedRevision. Same-ID mutated published calls fail closed. Error delivery verifies exact pending arguments like successful results, journals before send, and preserves uncertainty on lost responses. No failed render can become human consent.

Full gateway tests cover exact journal at provider-call boundary, reopen/deduplication, feedback-derived partial update, absent-source correction and mutated-refusal blocking.
