# A2UI graph backend contract v1 — 2026-10-28

Status: implemented bounded gateway execution path; offline HTTP/SQLite/Agents transport acceptance only. No new paid-provider or coordinated native end-to-end acceptance yet. Existing `/v1` routes and legacy `a2ui` form input remain compatible. Native implementation is owned separately; no iOS edits in this workstream.

Machine schemas: `a2ui-graph-input-v1.schema.json` (actual advertised tool graph branch) and `a2ui-graph-exchange-v1.schema.json` (graph surface/action/result/snapshot envelopes). JSON Schema validates structure; server additionally enforces ownership, pending calls, revisions, bounds, graph references, safe keys and context semantics.

## Function request

Tool `euphoria_render_surface` additionally accepts `{a2uiGraph:[message,...],expectedRevision?:integer}`. Do not mix this with native nodes or legacy a2ui. `message` is exactly `{version:"v0.9",createSurface:{surfaceId,catalogId}}`, `{version:"v0.9",updateComponents:{surfaceId,components}}`, or `{version:"v0.9",updateDataModel:{surfaceId,path?:string,value?:JSON}}`. All unknown fields fail. Function arguments may be JSON objects or bounded JSON strings from Agents API. Temporary normalization state only; existing sessions/surface_versions persist authority.

Catalog exactly `https://a2ui.org/specification/v0_9/basic_catalog.json`. References: pinned `@a2ui/web_core@0.10.4` `src/v0_9/processing/message-processor.js`, OpenDuet `openbot/app/src/lib/copilot/a2ui.tsx` baseline5b0e15f. Source component updates upsert by ID and replace that component's properties. Data updates replace a subtree; omitted value removes the named property, omitted path means root. Final complete graph must validate atomically. Existing source ID cannot be recreated without deletion; revisioned updates are required. Surface deletion, relative/array/escaped paths, executable functions, dynamic lists and ten unrendered catalog types are explicitly unsupported.

New graph: createSurface then component/data operations, max40 messages. Initial graph must be one tree rooted `root`, max200 unique nodes/depth24, child list max40. Supported: Column/Row(children); Card(child); Text(text,variant?); TextField(label,value?); CheckBox(label,value); ChoicePicker(label?,options,value,variant?); Button(child,action,variant?). Text variants h1–h5/body/caption, button primary/borderless, picker mutuallyExclusive/multipleSelection. Labels/text may be literals or `{path:"/safe/named/path"}`; control values may be bound or constant, only bound values are editable. No align/justify/filter/regex/theme silently ignored. Root may have nested cards/rows and shared bindings. All nodes must be reachable once; no orphan/cycle/repeated placement. At least one event Button is required (native read-only graph receipt is not implemented). This restriction is explicit, not a claim of full catalog parity.

Safe identities/property keys: ASCII letter/underscore followed by up to63 letters/numbers/underscore/hyphen; exclude __proto__/constructor/prototype. Paths max8 segments/256 UTF16 units. Strings max2000 UTF16 units, objects/arrays max80 members/depth12, aggregate model+properties budget4096 values. Choices max20 exact UTF16 values, distinct, valid initial membership and exclusive cardinality. Button event context max20 scalar or string-list values; objects/functions/null events refused. Authoritative graphs never accept localEdits.

Update graph: expectedRevision must equal saved outer revision, source surfaceId stays fixed. Apply source operations to a copy of the persisted graph and validate it before publication. Failures leave previous surface/version unchanged. Each new valid pending call increments outer AND embedded revision once. Re-reading the same immutable call does not apply its operations again. New graph with a distinct source ID can replace previous presentation.

## Publication and native action

Publication is existing `VisualSurface` schemaVersion2 with `nodes:[{id:"composition",kind:"sourceComposition",title:"Interactive workspace",composition:{version:"v0.9",surfaceId,catalogId,revision,components,dataModel,localEdits:{}}}]`. Outer surfaceID is gateway-generated and stable for the session; embedded surfaceId is source event identity. Existing snapshot envelope remains `{sessionID,title,phase,verificationMode,publication,failure?,surface,acknowledgedActionIDs,rejectedActionIDs,displayAcknowledged,resolvedNodeIDs}`. Existing SSE event shapes are unchanged: `event: update`, JSON `data: {snapshot,history,inputs}`; graph is inside snapshot.surface. No parallel graph event stream. See gateway/live-snapshots.mjs for exact transport envelope.

`POST /v1/surfaces/:gatewaySurfaceID/actions`: existing `{id,surfaceID,expectedRevision,nodeID:"composition",kind:"submitForm",values:{"$button":buttonID,"context:key":scalarOrStringList,...}}`. All event fields must be present exactly once; no extra fields. Server reconstructs permitted editable bindings from context, checks all controls sharing each path, refuses conflicting aliases, and recomputes event. Noneditable paths and literals cannot change. Client name/source/timestamp never confer authority. Displayed receipt cannot satisfy a graph Button.

Result to actual pending call: `{userAction:{name,surfaceId,sourceComponentId,timestamp,context}}`. Server assigns timestamp once before journalled submission. Exact pending turnID/callID/name AND argument fingerprint are checked, both at gateway admission and transport write. Existing action idempotency key prevents concurrent/double/restart writes; accepted event resolves the whole graph for that call. A new pending call can present a new revision. Approval is not external execution; source graph functions cannot grant tools or effects.

## Authentication, cancellation and recovery

Existing injected authentication maps server principal, never client owner. Session, surface, history, SSE and action remain owner-scoped. Provider cancellation removes the call's authority; old actions fail409. Live refresh and action writes use existing per-session lock. SQLite intent persists before submission; surface versions use existing journal. Additive actions.failure TEXT column contains only `{kind,stage,status?}`; original action payload stays immutable. Old SQLite data is migrated in place; old unknown effects remain unknown. No raw provider exception/content/secret is forwarded.

Confirmed validation/pending lookup failure means not_sent. Verified submission4xx except408 means rejected. Network/write5xx/408/invalid accepted response/missing or inconsistent metadata mean uncertain. Snapshot failure carries sanitized classification. Definite failed actions remain journalled and cannot replay under a new ID for that call; refresh/new agent call is required. Unknown effects remain blocked through restart. Historical render-refusal uncertain case cannot be reclassified merely because current tests pass; no automatic retry or invented acceptance. Existing reconciliation only cancels unknown local IDs, never submitted journal records.

## Fixtures and remaining acceptance

Source graphs: gateway/tests/fixtures/a2ui-graph-{trip,deployment}-v09.json. Versioned examples: docs/contracts/fixtures/a2ui-graph-v1.json. Synthetic names only; no provider credentials. Offline tests use actual HTTP and disk SQLite plus injected provider transport; real Agents API output submission is separately unverified for graphs. Full native-created positive/failure journey, cloud identity/deployment, APNs and service parity remain open. No claim that a localhost endpoint is a hosted product.

Provider event acknowledgement is restricted to verified HTTP202; a different successful status (including200/204 with parseable unrelated metadata) stays uncertain. Already-decoded and string function arguments are bounded before fingerprinting (128KiB wire, depth48,20000 values). Oversized/deep untrusted arguments fail502 without journalling or posting a refusal because a safe exact call fingerprint could not be established.
