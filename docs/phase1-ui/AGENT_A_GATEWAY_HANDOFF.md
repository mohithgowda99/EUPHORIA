# Agent A contract requests, no backend changes by Agent B

1. **Admit general A2UI surfaces:** one authenticated endpoint or existing tool-result projection accepting validated v0.9 createSurface/updateComponents/updateDataModel/deleteSurface *in order*, refusing unsupported catalog IDs, custom functions and malformed repeated scopes. Correlate session, turn, tool call, surface ID, canonical revision and user ownership. Reject stale/duplicate operations; publish authoritative snapshots. Do not assume replacing components equals complete stream support.
2. **Typed user action bridge:** maintain existing action journal; verify user, surface ownership, agent pending function call, current revision, permitted action/event schema, and idempotency key. Resolve context against current authoritative bindings. Return receipt and revisions; never let a UI tap execute external side effects without policy.
3. **Template instances:** define source-compatible `componentId,path` expansion and relative binding/event context semantics, item insertion/deletion/moves and stable row identity, including agreement with client revision snapshot. This frontend intentionally rejects templated children until that contract is ratified.
4. **Media and icon policy:** define HTTPS asset allowlist/proxy/redirect rules, authentication-free media URLs, content length/type limits and revocation. SVG path glyphs require separate validation and sanitization; current native icon renderer limits to enumerated names.
5. **Gallery and GenUI:** published component schemas/grants/descriptions, artifact revision storage/restoration, isolation policy, and a narrowly typed capability/action message protocol with sequence and replay verification. No general-purpose WKScriptMessageHandler or direct network bridge will be enabled here.
6. **Product UI sources:** typed status and permission envelopes for Bots/memory/skills/connections/routines/channels/admin/media/computer; existing Tasks and session contracts must be reused without changing their behavior.

Agent B will not implement or fake these server behaviors. Failure of a backend contract means the UI stays visibly unverified/fixture-backed, never falsely successful.
