# Live native session snapshots

User authorized continuing credential-independent phase-one work while obtaining an API key. Implement live gateway/native updates and recovery; no actual provider claims. Official Agents events/items guide and streaming-event schema fetched2026-10-28: GET sessions/:id/events?stream=true with Beta+Bearer headers. Subscribe before retrieving restoration state, use saved items/current required_actions on reconnect, never infer success from idle/EOF or replay input/approvals.

Approaches: forwarding raw provider events would expose unnecessary tool/private payloads and duplicate state; polling-only would not implement event consumption. Selected implementation: consume provider SSE, coalesce notifications into authenticated authoritative gateway snapshot/history/input-receipt updates. Reuse existing validators, renderer, SQLite/SwiftData journals. This first slice does not advertise token-by-token output or complete source streaming parity.

Provider transport: bounded UTF8 SSE framing, multiline/comment/CRLF support, sanitized errors, external redirects refused, explicit cancellation/timeout, no secret/raw event logging. Events must match session identity; provider bodies never pass through to native clients. Stream remains open across idle/turn events; those only trigger restoration reads.

Gateway: owned GET /v1/sessions/:id/events, subscribe upstream before initial snapshot. Coalesce read refreshes, bounded per-session streams and finite stream lifetime, heartbeat/comments, bounded backpressure, cancellation on disconnect/shutdown. Recheck injected identity before publication. Snapshot+bounded newest history+input receipts are published atomically as one SSE update; only already-sanitized projections. A persistent monotonic publication number on existing session rows prevents late stream/HTTP envelopes from rolling back acknowledged state. No separate event store/replay log. Writes still use existing per-session lock and idempotency journal; stream lifetime never holds that lock. Closed/failed streams are not successful actions.

Native: bounded SSE parser + secure URLSession subscription, same bearer/redirect restrictions. View follows only selected foreground session. Cancellation/new selection invalidates old callbacks; one latest update buffers while a local request is in flight and drains after it. Ignore older publications. Reconnect uses fresh snapshots/items, never resends work; bounded exponential delay, stop on auth/unavailable/failed session. Existing completed history items cannot regress to partial records. Status/error UI distinguishes live/reconnecting/unavailable while manual refresh remains usable.

Acceptance: adversarial framing/oversize/invalid/foreign events; HTTP ownership, nonblocking mutations, revoke/disconnect/shutdown and safe restoration; native typed parser/order/re-entry/foreground task behavior; full suites and Debug/Release. Local QA is explicitly labelled. Live OpenAI, distributed deployment, webhooks/background scheduling and complete token/AG-UI parity stay pending.
