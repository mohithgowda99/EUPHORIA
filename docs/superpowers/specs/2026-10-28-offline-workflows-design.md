## Recovery correctness
Current refuseRender catch maps every error to uncertain, losing whether a write was attempted. The provider adapter must classify errors with a fixed failure stage (validation/read/submission/response), optional integer HTTP status and outcomeUnknown. Preflight/GET failures mean no POST was sent; explicit4xx except408 means rejected; lost POST/5xx/408/invalid successful-response body remain uncertain. Persist sanitized classification in the existing action payload, no bodies/URLs/messages/credentials. Refusal_not_sent and refusal_rejected are terminal locally and never blindly retried; expose safe fixed guidance in session envelopes. Existing uncertain rows remain uncertain. No silent repair of the historical failure, no paid reproduction. Unknown provider errors conservatively uncertain. Tests pin wire shape, exactly-once/restart, classification and no secret leakage.
